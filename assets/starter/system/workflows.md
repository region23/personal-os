# Порядок работы

Пути — от корня базы. Разбор входящего — скилл `.agents/skills/inbox/`, обзор недели — `.agents/skills/weekly-review/`. Здесь — остальное.

## Формат записи

Обычный Markdown. Для существенного события хватает таких полей (пустые не пиши):

```text
Дата события: ...
Дата записи: ...
Источник: со слов владельца / файл / ссылка
Статус: факт / идея / предложение / принято / в работе / сделано / отменено

Суть: ...
Неизвестно: ❓ ...
Следующее действие: ...
Срок: ...
Связано: ...
```

Повторяющиеся измерения — CSV с заголовком, единицами и датой в каждой строке. Обмен с приложением — JSON с описанной схемой. Меняешь формат — сохрани старую историю и проверь перенос.

## Ответ на вопрос

Найди основную запись и её историю. Разделяй «верно сейчас» и «было верно тогда». Давай ссылки на файлы, из которых взял ответ. Меняющиеся внешние сведения (цены, правила, расписания) проверяй по актуальным источникам или говори, что не проверил. Если вопрос привёл к решению — запиши его.

## Расхождение и исправление

Разные даты — обычно изменение обстоятельств: обнови текущий README, история остаётся. Два источника спорят об одном событии — покажи владельцу обе версии и сохрани вопрос в `now.md` → «Открытые вопросы». После ответа исправь основную запись и все указатели; в журнале или CSV добавь поправку со ссылкой на ошибочную строку.

## Новый агент или компьютер

1. До переезда сохрани в базу всё, что осталось только в чате.
2. Перенеси папку целиком приватным способом. Внешние файлы, доступы и синхронизацию проверь отдельно.
3. В новом агенте дай стартовую фразу из `README.md`. Проверь: агент называет текущий фокус со ссылкой на `now.md` и находит последнюю запись в `journal/`.
4. Сохрани одну новую заметку и найди её повторно.

Переезд закончен, когда прошли все три проверки: правила прочитаны, контекст восстановлен, запись сохраняется. Подключения проверяй по `system/integrations.md` отдельно.
