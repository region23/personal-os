# Разобрать входящее

1. **Собери список.** Файлы в `inbox/` (кроме `README.md`) и всё, что владелец прислал или надиктовал в этом сообщении. В одной заметке бывает несколько тем — дели.
2. **Определи для каждого элемента, что это:** факт, событие, решение, идея или поручение. Идея не становится задачей, пока владелец не сказал, что будет её делать.
3. **Найди место** по карте в `README.md`:
   - текущее положение дел → README раздела, с датой «(на ГГГГ-ММ)»;
   - событие, разбор или решение → журнал раздела или `journal/ГГГГ/ГГГГ-ММ-ДД.md`;
   - срок или поручение → `now.md` → «Сроки»: действие, дата с часовым поясом, статус, ссылка на основную запись;
   - повторяющиеся измерения (вес, давление, расходы) → CSV в разделе с заголовком и единицами;
   - новая тема → новая папка с `README.md` и строка в карте.
   Место неочевидно — предложи самый вероятный вариант и спроси. Совсем неясное оставь в `inbox/` с конкретным вопросом.
4. **Проверь дубли.** Если это уже записано — дополни существующую запись, а не создавай вторую.
5. **Запиши.** Дата события отдельно от даты записи, если они разные. Источник: «со слов владельца», файл или ссылка. Неизвестное — `❓`.
6. **Файлы из `inbox/`** после записи перенеси в папку раздела. Чувствительный документ (паспорт, договор, медицинский) — сначала спроси, где ему лежать; в базе можно оставить только путь, ключевые факты и срок.
7. **Проверь.** Перечитай изменённые файлы и ссылки. Если Git выбран — один коммит на весь разбор.
8. **Отчёт.** По строке на элемент: «что → куда». В конце — одно следующее действие, если оно есть.

Готово, когда в `inbox/` остался только `README.md` (или вопросы к владельцу), а каждый элемент сообщения есть в отчёте.
